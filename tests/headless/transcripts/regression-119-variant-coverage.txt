# REQ-119 increment 2 (GitHub issue #81) — every token the marked-up prompts now offer is
# ACCEPTED by the command showing that prompt, in that state.
#
# Increment 1's transcript (regression-119-variant-token-accepted) pinned the three prompts the
# mechanism itself touched. This one pins the coverage pass: ~30 prompt strings across both hint
# families gained `[TOKEN]` markup, and each token here is submitted in the state whose prompt
# offers it. A token that stops being accepted fails HERE rather than becoming a link that looks
# actionable and silently does nothing — which is strictly worse than plain text, because plain
# text does not invite the click.
#
# ## The exclusion this file exists to defend
#
# CIRCLE's radius prompt says "D <value> or D<value> for diameter". D is a VALUE PREFIX, not a
# submittable token: bare "d" is refused by ParseRadiusOrDiameter, because ParseOneFloat("")
# fails on the empty remainder. It is therefore deliberately NOT marked up — marking it would
# manufacture exactly the dead link REQ-119 exists to remove. The refusal is asserted live at the
# bottom of this file, so a later well-meaning markup pass fails the build instead of shipping it.

NEW
