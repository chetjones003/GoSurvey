# REQ-121 / GitHub #91 review — DELETE and JOIN accumulate until Enter (D-2026-08-26-d).
#
# ## What this is fixing
#
# PR #102 gave every object-selection step one shared prompt, "Select objects, ENTER to continue".
# For DELETE and JOIN that sentence was FALSE: both were fixed two-click-box commands, the box
# executed the command the moment it closed, and `ProcessCommandLineSubmit` answered Enter with
# "finish window-select in the viewport (two clicks), or ESC to cancel." The prompt told the user to
# press a key the command explicitly refused.
#
# D-2026-08-25-l had already given click-or-box-accumulate-until-Enter to MOVE / COPY / SCALE /
# ROTATE / MIRROR / ALIGN / ARRAY, and excluded STRETCH for a stated reason (its crossing box is
# load-bearing geometry). DELETE and JOIN were simply never included — the same omission class as
# ALIGN's snapped box corners, which this issue already fixed. So the behaviour was corrected to
# match the prompt rather than the sentence weakened to match the behaviour.
#
# ## What is asserted here, and why each line is load-bearing
#
# The single most important assertion is `EXPECT LINES 3` immediately after the first box closes.
# Before the fix that box ERASED, so the count was 2 and the command had already ended. Everything
# after it — accumulating a second box onto the first, Enter being what acts — is only reachable
# because the box no longer ends the command.
#
# `CLICK` rather than `PICK` throughout: CLICK asks `ViewportClickRouteFor` the same question
# `DrawDrawingViewport` asks, so this transcript also pins the ROUTE change (DELETE/JOIN moved from
# `SelectionBox` to `SelectionAccumulate`). A PICK-based transcript would pass even if the routing
# were reverted, which is exactly the failure mode the CLICK verb was added for (TASK-099).
#
# What is NOT covered here, and cannot be: a click that lands ON an entity toggles just that entity
# into the selection. That is screen-space picking with no headless equivalent (the driver's own
# note on `SelectionAccumulate` says so), so CLICK always behaves as a fence corner. The click-on-
# entity half is in the manual GUI pass, TASK-118 §13.
