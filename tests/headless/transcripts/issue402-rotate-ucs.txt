# GitHub issue #402 / REQ-329 increment 2 — ROTATE turns the selection about an axis through the
# picked base point PARALLEL TO THE ACTIVE UCS Z (REQ-328's `RotateSelectionAboutAxis` primitive),
# not always world Z.
#
# Regression guard: plan view, and any UCS whose Z axis is still world-Z-parallel (rotated in plan),
# go through the unchanged `ApplyRotationToSelection` / `DuplicateCadSelectionRotated` — byte-identical
# to before. Only a genuinely TILTED UCS takes the new axis-aware path.

# --- Regression: World UCS, typed ROTATE 90 about the origin (CW in plan) -------------------------
NEW
CMD LINE
CMD 10,0
CMD 20,0
ESC
BOX 5 -5 25 5
EXPECT SELECTED 1
CMD ROTATE
CMD 0,0
CMD 90
ESC
# 90 CW-from-north about world Z: (10,0)->(0,-10), (20,0)->(0,-20).
EXPECT LINEXYZ 0 0 -10 0 0 -20 0
CHECK ALL

# --- Regression: World UCS, PICKED angle ---------------------------------------------------------
NEW
CMD LINE
CMD 10,0
CMD 20,0
ESC
BOX 5 -5 25 5
CMD ROTATE
CLICKUCS 0 0
CLICKUCS 0 -10
ESC
# base (0,0), cursor straight down (0,-10) => -atan2(0,-10) = -pi => 180 deg.
EXPECT LINEXYZ 0 -10 0 0 -20 0 0
CHECK ALL

# --- Tilted UCS (X 90): typed ROTATE 90 spins the selection about the UCS Z axis -----------------
# UCS X 90: basis X=(1,0,0), Y=(0,0,1), Z=(0,-1,0). Line at UCS (0,0)-(10,0) = world (0,0,0)-(10,0,0).
# ROTATE base UCS (0,0), angle 90 (rad = -pi/2). Rodrigues about (0,-1,0) by -pi/2 sends
# world (10,0,0) -> (0,0,-10). The base endpoint is on the axis and does not move.
NEW
CMD UCS
CMD X
CMD 90
CMD LINE
CLICKUCS 0 0
CLICKUCS 10 0
ESC
BOX -5 -5 15 5
EXPECT SELECTED 1
CMD ROTATE
CLICKUCS 0 0
CMD 90
ESC
CMD UCS
CMD W
EXPECT LINEXYZ 0 0 0 0 0 0 -10
CHECK ALL
