# A box selection in an ORBITED view must select what the fence actually encloses, on a work plane
# that is not at elevation zero (user report, 2026-09-01).
#
# The defect: both the drawn selection rectangle and the region that selects projected their two
# drag corners at Z = 0, while LINES project at their true Z ("lines are projected endpoint-wise and
# stay exact" - ComputeSelectionFromRect's own note). On the world XY plane at elevation zero those
# agree, and in plan view Z does not move a projection at all, so it was invisible in the default
# view and in every existing transcript. Raise the work plane with ELEV, or tilt it with a UCS, and
# the fence lands on pixels the mouse never visited.
#
# This is the first transcript to ORBIT the view, which is why the defect had no failing test
# available to it: picking, snapping and box-selection all leave the plan-view XY path and become a
# camera projection off plan view (REQ-058). Each case gets a fresh drawing, and each hit is paired
# with a deliberate MISS - otherwise a stale selection would let a broken fence pass.

# --- Plan view at elevation 50: the control ---------------------------------------------------------
NEW
CMD ELEV
CMD 50
ESC
CMD LINE
CMD 0,0
CMD 20,0
ESC
EXPECT LINEXYZ 0 0 0 50 20 0 50
BOX -10 -10 30 10
EXPECT SELECTED 1

NEW
CMD ELEV
CMD 50
ESC
CMD LINE
CMD 0,0
CMD 20,0
ESC
BOX 200 200 240 220
EXPECT SELECTED 0
