# TASK-299 — GoSurvey's own LibreDWG: build it from source in this repository

- Type:    chore (build) + bug (GEODATA layout)
- Status:  submitted
- Opened:  2026-09-30
- Owner:   Workshop

## 1. Authority

- ADR-041 (h), D-2026-09-30-d (accepted 2026-09-30): GoSurvey maintains its own LibreDWG as full
  library source in `third_party/libredwg/`, compiled by the GoSurvey build; the prebuilt `.lib` is
  removed; every change is its own commit listed in `VENDORED.md`; the first change removes the extra
  bit in the R2000 GEODATA layout (REQ-362 item 3). REQ-205's clean-build budget must still hold.
- REQ-362 acceptance (write, accepted): "a small R2000 fixture that AutoCAD saved with a GEODATA reads
  with the values AutoCAD reports (guards the corrected LibreDWG layout)".
- REQ-170 (the codec), REQ-200 (identical builds), REQ-205 (build time).
- Owning subsystem: Build (`CMakeLists.txt`, `third_party/libredwg/`), IO (tests only).

## 2. Scope

- In scope: vendor upstream 0.13.4's library source unchanged (commit 1); build it with our own CMake
  target; remove the prebuilt lib; correct the stale "0.13.3" version strings; the GEODATA layout fix
  with its fixture test (commit 2); measure REQ-205.
- Out of scope: GEODATA writing (REQ-362 item 2, next task); moving the #590 entity-link workaround
  into LibreDWG (it stays in `LibreDwgLinkBlockEntities`); upstream reporting.

## 3. Architectural boundary check

- [x] Covered by an accepted decision (D-2026-09-30-d / ADR-041 (h)); no further architectural choice.
  Upstream's CMake is not used (its ~30 `try_compile` probes were half of the old from-source cost,
  issue #142); a committed `config.h` generated by upstream's CMake for MSVC x64 replaces them.

## 4. Plan

- `third_party/libredwg/`: upstream's tracked `src/` + `include/` at 0.13.4, `programs/my_stat.h`
  (included by `dwg.c`), COPYING/AUTHORS/README/NEWS, generated `src/config.h`; `VENDORED.md` rewritten.
- `CMakeLists.txt`: `add_library(libredwg STATIC …)` with upstream's 21 library-only sources (JSON off,
  write on), C99, `/w /utf-8`, `_CRT_*_NO_WARNINGS`; PUBLIC `include/`; `ws2_32`;
  `GOSURVEY_LIBREDWG_VERSION="0.13.4"`.
- Tests: the whole suite on the source-built library; the version test now expects 0.13.4.
- REQ-205: time a clean `ninja-release` build of this tree and of `beta` on the same machine.

## 5. Implementation log

- 2026-09-30: the vendored headers and `config.h` were already 0.13.4 (`PACKAGE_VERSION
  "0.13.4-0-ge3774bd"`); only the CMake define, one test and some comments still said 0.13.3.
- 2026-09-30: first build failed: `dwg.c` includes `../programs/my_stat.h`; that one header is
  vendored. `in_json.c` (the only other outside include) is not built.
- 2026-09-30: build clean; `./dev/test` 2011/2018, the same 7 headless transcripts that fail on beta;
  all `[libredwg]`/`[dwg]`/`[dxf]`/`[req362]` cases pass.

- 2026-09-30: REQ-205 measured (clean `ninja-release`, all targets, same machine, separate build
  dirs, one after the other): beta with the prebuilt lib **94 s**; this tree **146 s**. LibreDWG's
  `encode.c` / `out_dxfb.c` / `decode.c` / `in_dxf.c` take ~16 s each alone but 70–115 s under the full
  parallel build, and every link waits for the library. With LibreDWG at `/Od` the clean build is
  **98 s**; the codec then reads the 3.4 MB Civil 3D sample in 0.10 s instead of 0.06 s and writes
  50,000 lines in 0.17 s instead of 0.14 s. Asked the user (ADR-041 (h) said "the same MSVC
  configuration"): keep `/O2` and raise the budget to ~2.5 min — D-2026-09-30-e, REQ-205 updated.
- 2026-09-30: GoSurvey change 1 (`dwg.spec`): the extra `unknown_b` removed. `ReadDwgGeoData` reads
  the class-version-1 meaning (reference = (lat, lon), north = radians from +Y). Fixture
  `samples/geodata-r2000-autocad.dwg`: the `TX83-CF` spike file re-saved as R2000 by AutoCAD 2027
  (AutoCAD rewrites every object); its GEODATA decodes to exactly its bit size with the corrected
  layout (independent Python decoder).
