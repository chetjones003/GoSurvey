# TASK-732-p7 - Automatic alignment and change detection (REQ-393, REQ-392 clause 3, ADR-067 addendum 2, D-2026-10-06-f)

- Status: submitted
- Requirement authority: REQ-393 (accepted, spec PR #741 merged), clauses 1-6; and REQ-392 clause 3 (automatic alignment) with its first acceptance test, which phase 6 (PR #747) left for this phase as the roadmap and D-2026-10-06-f order them. Stacked on PR #747 (the comparison view).
- Scope: `src/pdf/PdfAlign` gains `AutoAlign` (ink profiles give a starting shift; iterative closest point on a chamfer nearest-ink map fits shift, uniform scale and rotation up to 5 degrees; confidence = share of revision ink within about 2 pt; under 60 % no match is claimed and the identity is returned); `src/pdf/PdfDiff` (pure: `FindChanges` - ink masks, tolerance dilation, Added / Removed / Changed regions merged by distance, specks dropped; `RegionsToMarkups`); the Rect annotation now carries its comment (`/Contents`) both ways; `PdfCompare`: automatic alignment on opening and on a page change, **Align automatically**, **Find changes** with progress and Cancel, tolerance and minimum-size settings, change list (click centres it), Next / Previous (buttons, N / P), translucent highlights (green / red / amber, hideable) in every view including the new plain **Base** and **Revision** views, **Write changes as markups...** (one Rect per region on a Save As copy of the revision), the stated limits and a low-confidence warning; `BENCH PDFDIFF` + `pdfdiff-bench` DevShell test and `MakeLineWorkPdf`.
- Approach: the search runs on one worker at a time (alignment, then comparison), each rendering the pages itself at a working resolution (alignment 1 px/pt, comparison 1.5 px/pt, both capped), so the UI thread only starts it and collects the result. Reset now returns to the automatic alignment.
- Assumptions (recorded, not asked): defaults tolerance 1 mm (the spec's), minimum region size 2 mm, merge distance 4 mm (the spec names a minimum size setting but no default or merge distance); a region holding both added and removed marks is Changed, so a line moved a few mm is one Changed region and one moved further is a Removed plus an Added; low confidence under 60 %; the rotation limit is 5.5 degrees; annotations on the pages are drawn into the comparison as ink; settings live in the comparison view and are not saved between sessions; the markup note reads "Added, 12.3 x 4.5 pt" in points.
- Technical debt: the automatic alignment assumes a similar-looking pair (a changed scale between revisions beyond a few percent, or a scanned sheet, can fail to match - flagged by the low-confidence warning, manual alignment remains).
- Verified: `tests/PdfDiffTests.cpp` 6 cases / 56 assertions: auto-alignment recovers a known shift + 1.01 scale + 2 degree rotation within 0.5 pt at the page corners and centre; an unrelated pair claims no match; identical sheets and a 0.7 px wobble give zero regions; one added, one removed and one moved line give exactly one Added, one Removed, one Changed region each holding the true spot and a 2 pt speck is dropped; a 5 pt shift gives zero changes after automatic alignment and more than five without it; Write-as-markups saves one Rect per region with the right kind, colour, comment and box and leaves the source bytes identical. Full `[issue732]` group: 61 cases pass. `BENCH PDFDIFF` (DevShell, generated 36 x 24 in sheets with 60000 segments each): alignment 1033 ms + comparison 1399 ms = 2.4 s (target 10 s), worst viewer frame while it ran 0.31 ms (target 16 ms). `BENCH PDFCOMPARE 500` still p95 1.34 ms, worst 3.03 ms. Not verified by a person: the look and feel of the list, highlights and Write-as-markups, and the real-plan spot check REQ-393 asks for (a recorded comparison with what a person marks by eye).
