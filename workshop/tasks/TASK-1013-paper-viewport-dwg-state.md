# TASK-1013 — DWG paper viewport state (issue #1013)

- Type: bug fix
- Status: in progress
- Opened: 2026-10-25
- GitHub issue: #1013

## 1. Authority

- Requirement: REQ-113 (accepted), extended by D-2026-10-25-a/b.
- Related requirements: REQ-061 camera, REQ-046 VP color, REQ-155 active UCS, REQ-170 DWG codec.
- Acceptance: REQ-113 additions (9)-(12); full viewport state must use native AutoCAD viewport/layer data and round-trip through both DWG and DXF.

## 2. Scope and implementation plan

- Add an independent per-viewport annotation-scale choice backed by the drawing's annotation scale list. Initialize new viewports to the drawing's current scale; expose the choice in the existing viewport controls independently from zoom.
- Export/import camera including projection, layer color overrides, active UCS frame, and per-viewport annotation scale through both DWG and DXF, while preserving the already-supported scale, view direction, twist, frozen layers, lock/on/off and visual style.
- Use the current `Viewport` and LibreDWG import/export paths for files containing the added native viewport records. Keep the established DXF codec for files that do not need those records because its ordinary entity coverage is broader. DXF serialization is always R2018 regardless of the DWG preference. Add no abstraction or dependency.
- Add coverage at the user-visible seams: changing the viewport annotation scale in the viewport controls, new viewport initialization, and DWG export/import round-trip for each added property, plus missing-field defaults for legacy DWGs.

## 3. Files / subsystems

- `spec/project.md`, `spec/requirements.md`
- `src/commands/PaperSpace.hpp`, viewport creation/state helpers, and `src/io/GsIo.cpp` for the viewport value
- `src/io/DxfIo.cpp` public entry points and `src/io/LibreDwgCad.cpp` shared codec for native viewport fields in DWG and DXF
- Existing Qt viewport controls in `src/qt/EditorWindow.cpp`
- `tests/LibreDwgCadTests.cpp`
- This task record

## 4. Architectural-boundary check

`Viewport` owns its own annotation-scale selection and the existing camera/color/UCS values; viewport UI edits it and LibreDWG owns DWG encoding/decoding. The plan connects those existing owners. The required DWG representations must be native AutoCAD properties. The user selected LibreDWG as the sole writer; no AutoCAD runtime dependency or GoSurvey-only metadata is acceptable.

## 5. Verification plan

- Focused DWG and DXF viewport round-trip tests for camera/projection, VP colors, UCS and annotative scale.
- Qt viewport-control coverage for independent scale selection and default initialization.
- Existing paper-space DWG tests and relevant annotative-context tests.
- Full Windows build and CTest suite once at completion.
- Architecture and code review; record any AutoCAD oracle limitation explicitly.

- 2026-10-25 codec investigation: Decoding an AutoCAD-authored R2018 file exposed two additional AC18 container defects. Both are now implemented in the vendored encoder. The resulting minimal file passes LibreDWG's own reader with no decode errors, but AutoCAD still rejects it (Core Console exit 434), so this is progress toward the container fix, not acceptance. Continue comparing section maps and version-specific records; do not mark DWG complete or open a PR until AutoCAD accepts and audits the viewport round-trip.

- 2026-10-25 section-header comparison: The accepted AutoCAD file reports `last_section_id` as the highest ordinary data-page ID; it does not include the INFO and SYSTEM_MAP page IDs. Updating that field alone built successfully but Core Console still rejected the DWG. A further comparison showed the current writer derived `last_section_address` from the SYSTEM_MAP page, while AutoCAD’s ticket file has ordinary section pages physically after SYSTEM_MAP (its field equals the final page end minus 0x100). The writer now computes that field from the highest physical section-page end. This correction still requires build and AutoCAD validation.
- 2026-10-26 object-tail comparison: AutoCAD sets the trailing partial bits in R2007+ object records to one. The encoder previously zero-filled them. Comparing the minimal AutoCAD-authored object section with a fresh LibreDWG export showed the same final-byte mismatch across 10 common objects; after changing object-record padding to ones, all 33 shared object records match at their tail and 9 match byte-for-byte. This is a verified record-level correction. AutoCAD still rejects the fresh R2018 file with `ErrorStatus=53`, so further differences remain.
- 2026-10-26 R2018 header/map probes: A previously captured AutoCAD-authored gapless control uses 13 data-page IDs, INFO=16, SYSTEM_MAP=17, `section_array_size=17`, and `last_section_id=17`; the writer's former compact INFO/MAP IDs (14/15) did not match that control. The writer now reserves IDs 14/15 and emits 16/17 for R2013+ output. A fresh AutoCAD Core Console round-trip still fails with `ErrorStatus=53`, so this was not the sole cause.
- 2026-10-26 stream-order probe: AutoCAD-authored R2018 controls vary in physical page order. The ticket control places INFO after Template and SYSTEM_MAP after Header, with AcDs/Objects near the end; another accepted gapless control places AcDs and Objects much earlier. Tested the alternate order and `SYSTEM_MAP` reservation of `0x5c0`; it still failed, so the encoder retains the ticket order and its prior `0x660` reservation pending a correct source-order-preserving implementation.
