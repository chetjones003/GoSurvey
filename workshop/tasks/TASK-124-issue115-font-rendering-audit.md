### Round 2 — 2026-08-27 — response to review

Addressed the four items the review listed under "Recommended before close".

**1. Viewport MTEXT sizing (REQ-050).** The viewport text pass sized every annotation with
`CadAnnotationHeightWorld(ann, cmd.modelUnitsPerPlottedInch)` — the drawing's plot scale — so the same
MTEXT read at different sizes in model space and through a 1:50 vs a 1:100 viewport. The rule now
lives in one pure helper, `MtextScaleThroughViewport` (`PaperSpace.hpp`), which the overlay calls:
plain MTEXT takes the viewport's own scale, survey-point label MTEXT keeps the drawing scale
(REQ-050 states both). Single-line TEXT is untouched — REQ-050 keeps it on the drawing scale.

Verified on screen as well as in tests: the same MTEXT through viewports at 1:25 and 1:100 now reads
at one plotted size; before the change it was 4× larger in one than the other. Before/after captures
are attached to the PR.

**2. Isolation in the viewport text loop (REQ-084 (d)).** Added the `CadEntityIdHidden` guard the
model-space annotation loop already had. **The dimension-through-viewport loop had the same gap** and
was fixed too — the review named only the text loop.

**3. Fixture drawing.** `samples/font-demo.gs`, generated by `tools/Make-FontDemoGs.ps1` from
`tests/headless/transcripts/issue115-font-matrix.txt` (the `Make-SurfaceDemoGs.ps1` precedent), so it
is reproducible rather than hand-authored. Covers DIMLINEAR, DIMALIGNED, TEXT, MTEXT and native paper
TEXT across Arial / Times New Roman / `romans.shx`, in model space, on the sheet, and through two
viewports at different scales.

**4. Tests that can actually fail.** The `ModelToPaperIn` case the review criticised is replaced by
three REQ-050 cases against the shared helper. **Verified by reintroducing the defect**: with
`MtextScaleThroughViewport` returning the drawing scale, `[cadfont]` fails 2 assertions
(`100.0f == Approx(50.0)`); restored, it is green. A test that has never been seen to fail is not
evidence, which was the review's point.

### Known gaps, stated rather than closed

- **DIMANGULAR is absent from the fixture, and AC-4 cannot be fully verified.** Angular dimensions do
  not survive being saved: `GsIo`'s `AnnotationKindTag` has no `DimAngular` case so it falls to
  `default: return "text"`, and the angular geometry (`dimAngVertexX/Y`) is never serialized at all.
  Reproduced minimally: create one, `SAVEAS`, and the file says `"kind": "text"`. Putting one in a
  sample drawing would ship a silently-corrupted annotation. **This is a separate data-loss defect,
  not a font one** — the code is untouched by this branch and the same behaviour is on `beta` — so it
  wants its own issue and its own fix rather than being folded in here.
- **MTEXT is injected into the sample, not drawn.** MTEXT content comes from the on-screen editor, so
  no transcript can create one. The generator says so at the injection site.
- **Which glyphs are drawn is still not asserted anywhere.** The headless driver has no font atlas —
  `FontRegistry` answers with the default font when the atlas is locked — so a transcript can see the
  arithmetic that sizes text but not the typeface that renders it. Verifying Arial vs Times vs
  `romans.shx` remains a visual check, which is what the fixture is for. Closing that would need a
  render-capture harness, which is a larger piece of work than this issue.
