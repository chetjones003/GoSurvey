# TASK-732-p2 - PDF annotations: text, line, rectangle, ellipse, Save As (REQ-388, ADR-067 (e), D-2026-10-06-a/-e)

- Status: submitted
- Requirement authority: REQ-388 (accepted; clause 2 revised by D-2026-10-06-e, spec PR #739), depends on REQ-387 (merged). Constraints: REQ-201 (honest messages), REQ-300 (no new dependency), REQ-100 frame budget.
- Scope: `src/pdf/PdfAnnotate.{hpp,cpp}` (pure: `Annot`, `AnnotSession` undo/redo, `SaveAnnotated`, `ReadAnnotations`); annotation row, overlay drawing, select/move/resize/delete, note dialog, unsaved-changes prompt in `src/ui/PdfViewerWindow.cpp`; `FontReg::FindTtfPath` (so the viewer offers the fonts GoSurvey already loads); tests `[pdfannot][req388][issue732]`.
- Approach: edits live in memory and are drawn over the page by ImGui (a page is never re-rendered for an edit). Save As: PDFium writes Square and Circle (with a hand-built appearance) directly; Text and Line are created as Stamp placeholders carrying their drawn objects (PDFium builds the appearance and font resources), then the saved bytes are patched in place at the same total length to the true FreeText / Line type (colour, border and line end points ride in that patch because PDFium refuses colour on a Stamp). Written to a temporary file, renamed into place; the source is read once into memory and never opened for writing.
- Architectural-boundary check: Domain/IO module is window-free and uses `PdfiumMutex()`; UI owns state and drawing; no new dependency; `FontReg` gains one read-only function.
- Assumptions: the on-screen note preview uses the closest installed face and a rough width estimate, so the saved text can differ slightly in width from the preview. Bold/italic of an embedded TrueType family uses that family's own bold/italic file when installed, otherwise the regular file. `.ttc` font collections (Cambria) are not offered. Prompt on close covers the viewer window, not quitting GoSurvey itself.
- Verified: unit tests (each tool writes and reads back its type, colour, thickness, font; rendering shows line/rect/ellipse/text in the right place; source bytes identical; replace-source refused; undo/redo exact). Not verified by a person: the on-screen tools and dialogs, or opening a saved file in a second PDF reader.
