# TASK-732-p5 - Scaled dimensions: length, polylength, area and perimeter, angle (REQ-391, ADR-067 addendum 2, D-2026-10-06-f)

- Status: submitted
- Requirement authority: REQ-391 (accepted, spec PR #741); depends on REQ-390 (merged, PR #742) and REQ-388. Constraints: REQ-201, REQ-300.
- Scope: `Annot` gains the kinds Length / PolyLength / Area / Angle (geometry in `pts`, label never stored); `PdfAnnotate` value helpers (`PathLengthPt`, `PolygonAreaSqPt`, `AngleDegrees`, `DimensionLabel`, `DimensionLabelAnchor`) and `SaveAnnotated` writing them; `ReadAnnotations` reading them; viewer Measure row (Length, Polylength, Area, Angle, decimals, label size), click-out input, live labels, select / move / drag a point / delete / undo; tests `[pdfdim][req391][issue732]`.
- Approach: each dimension is a PDFium Stamp placeholder carrying its drawn path and label (PDFium builds the appearance and font resources), rewritten in place at the same byte length (D-2026-10-06-e) to a true Line / PolyLine / Polygon with `/Measure` (the page's own measure dictionary, `BuildMeasureDict`), `/IT`, `/C`, `/Border` and `/Contents` (the label). Angle is a PolyLine with a private `/GSKind(angle)` mark and no `/Measure` (the standard has no angle dimension). On screen the label is recomputed every frame from the page's scale, so changing the scale updates every dimension (clause 4); Save As uses the scale in force on each page and refuses a dimension on an unscaled page.
- Spec correction (not a change of intent): the REQ-391 acceptance line said a 100 x 40 pt area at 1 pt = 0.5 ft reads "5000 sq ft" and "70 ft" perimeter; the right figures are 1000 sq ft (4000 sq pt x 0.25) and 140 ft (280 pt x 0.5). Corrected in `spec/requirements.md` in this PR; the implementation was right.
- Not done (declared out of scope by clause 5/6 or deferred): snapping to the PDF's own line work (clause 5: needs a vector-geometry reader, not started; the tools place points freely), area cut-outs, legend export. Clause 5 snapping is therefore an open item of REQ-391.
- Assumptions: label placement (longest segment middle / area centre / beside the angle corner); `/IT/LineDimension` etc. as the standard's dimension intent names; unverified in Bluebeam/Acrobat.
- Verified: unit tests (values on a 0.5 ft/pt page, angle cases, decimals, other scales, each kind saved and read back with geometry, colour, thickness and label, `/Measure` present on three of four, subtypes, source bytes identical, line drawn when rendered, scale change changes labels, unscaled page refused with nothing written, too-few points refused, angle needs no scale). Not verified by a person: the on-screen tools, and the files in Bluebeam/Acrobat.
