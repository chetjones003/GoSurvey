# TASK-732-p10 - Annotation fixes (Text placement, click-click drawing) and the Leader tool (REQ-396, D-2026-10-06-j)

- Status: submitted
- Requirement authority: REQ-396 (accepted with this task; the user asked for the fixes and the tool), builds on REQ-388.
- Root causes (found by reading the code, not guessed):
  - **Text lands at the page's left edge:** the note dialog built the note with `x0 = clicked x`, `y1 = clicked y` but left `x1 = y0 = 0`; `FitTextBox` anchors on `min(x0, x1)`, which was therefore always 0. Fixed: both corners start at the click.
  - **Line/Rectangle/Ellipse never finished by two clicks and showed no preview after one:** they were press-drag-release only. A plain click released at once, the shape was under 4 px, and it was thrown away, so there was never a preview. Fixed: a release that has not travelled leaves the shape waiting (`createSticky`), with the preview following the pointer; the second click finishes it. Drag still works.
- Leader: `Annot::Kind::Leader` (box = x0..y1, tip = `pts[0]`, `LeaderLine` geometry shared by the screen and the saved file); Leader tool button (tip click, then box click, then the note dialog); grips (tip, box corner), select / move / delete / undo, double-click edits text. Saved as one FreeText annotation with `/IT/FreeTextCallout`, `/CL` and `/LE/OpenArrow` via the existing placeholder-then-patch route; `GSLeader` carries the tip and box for our own reader.
- Files: `src/pdf/PdfAnnotate.{hpp,cpp}` (Leader kind, `LeaderLine`, `AddLeader`, shared `LoadNoteFont` / `NoteTextObjects` / `SetNoteEntries` split out of `AddText`, reader), `src/ui/PdfViewerWindow.cpp` (tool, drawing, hit test, grips, click-click flow, text-placement fix), `tests/PdfLeaderTests.cpp`, `CMakeLists.txt`.
