# Issue #807 — Autodesk Surface Control Behavior

Research date: 2026-11-06. Sources are official Autodesk AutoCAD Civil 3D documentation.
This note reports Autodesk behavior to inform GoSurvey's product decisions; it does not make
Civil 3D behavior an automatic GoSurvey requirement.

| Control | Autodesk-documented behavior | Scope notes / ambiguity |
|---|---|---|
| **Add Labels** | Civil 3D surface labels include contour labels (single, multiple, or at an interval), spot elevations, slopes, and watershed labels. Labels use configurable styles; labels are placed at a picked point, or along a selected/drawn path for contour labels. [Surface Labels and Tables](https://help.autodesk.com/cloudhelp/2025/ENG/Civil3D-UserGuide/files/GUID-652C9699-7DB5-4AB0-A7B9-AC3498FB6175.htm), [Exercise: Labeling a Surface](https://help.autodesk.com/cloudhelp/2025/ENU/Civil3D-Tutorials/files/GUID-96A2EEE7-BB4B-45D0-95F1-73CD5CC15921.htm) | “Add Labels” is a family of distinct workflows and label styles, not one well-defined action. GoSurvey must select which labels it supports. REQ-071 already bakes contour lines as ordinary polylines, but does not define labels. |
| **Add Legend** | Adds a drawing table for a surface analysis type: directions, levels, slopes, slope arrows, contours, user contours, or watersheds. The analysis must already exist; the user chooses a table style and insertion point and can make the table update dynamically. [To Add Surface Legend Tables](https://help.autodesk.com/cloudhelp/2026/ENG/Civil3D-UserGuide/files/GUID-71B14BC4-3AAE-4AEF-B7D8-ACD49DC902AA.htm) | Requires supported analysis and a table representation. GoSurvey has REQ-072 analysis but no accepted general surface-legend/table behavior. REQ-148's TABLE is for volume summaries. |
| **Point Files** | Adds a point file to a surface definition, with a selected/defined file format and file path; malformed lines are reported while processing continues. [Adding Surface Data from a Point File](https://help.autodesk.com/cloudhelp/2022/ENU/Civil3D-UserGuide/files/GUID-BCE90788-3B5B-49C7-A153-C9D3A0BA2DB4.htm) | Direct match to accepted REQ-086: linked point-file data contributes to the TIN without becoming survey points and is reread on rebuild. The ribbon action should expose that behavior, not import the file as survey points. |
| **Reduced LOD** | Uses fewer surface geometry triangles/regeneration for smoother performance at lower visual fidelity. It is a per-surface choice from the Surface ribbon; detail reduction is a display/performance mode. [Modify the Level of Detail of Surfaces](https://help.autodesk.com/cloudhelp/2025/ENG/Civil3D-UserGuide/files/GUID-5BC9F893-985E-4ED1-B37D-B22E099D8ABA.htm), [To Simplify Data Display](https://help.autodesk.com/cloudhelp/2024/ENG/Civil3D-UserGuide/files/GUID-F715FE3C-66CB-458B-848F-8743B2760F07.htm) | Autodesk preserves full detail for plotting and some surface components; edits requiring picking points/edges require full detail. GoSurvey must define whether LOD may omit draw geometry while retaining full query/pick/plot accuracy. |
| **High LOD** | Restores complete surface geometry triangles and normal surface regeneration for better visual fidelity, with higher system cost. It is a per-surface choice. [Modify the Level of Detail of Surfaces](https://help.autodesk.com/cloudhelp/2025/ENG/Civil3D-UserGuide/files/GUID-5BC9F893-985E-4ED1-B37D-B22E099D8ABA.htm) | Same GoSurvey decision as Reduced LOD: visual-only simplification versus changing stored/queryable geometry. |
| **Crossing BL** | Finds crossing breaklines in a survey database, figure, or surface; lists intersecting pairs and their coordinates/level difference; supports zooming to the intersection and resolving levels or trimming invalid segments. [To Find and Fix Crossing Surface Breaklines](https://help.autodesk.com/cloudhelp/2020/ENG/Civil3D-UserGuide/files/GUID-18B88760-3424-4270-AFC9-B845BD2000AA.htm), [About Surface Breakline Tools](https://help.autodesk.com/cloudhelp/2021/ENG/Civil3D-UserGuide/files/GUID-DF0D9C8E-F428-42EF-8A4B-1D8F5390DCD4.htm) | This is a diagnostic and edit workflow, not only a “check” toggle. GoSurvey would need define what constitutes a crossing, what fixes are safe, and whether it supports automatic edits. |
| **Visibility** | Civil 3D visibility tools include point-to-point line-of-sight (eye/target heights and positions, reports obstruction), zone-of-visual-influence (object height and radius, colored visible/partial/hidden regions), and roadway sight-distance checks. [About Visibility Checks](https://help.autodesk.com/cloudhelp/2018/ENG/Civil3D-UserGuide/files/GUID-23BFC7E4-7C48-409D-84B3-CD804D8F56E7.htm), [Point-to-Point Line of Sight](https://help.autodesk.com/cloudhelp/2022/ENG/Civil3D-UserGuide/files/GUID-280FC71E-373D-4CF0-9D02-9C9C61190CF6.htm), [Zone of Visual Influence](https://help.autodesk.com/cloudhelp/2025/ENG/Civil3D-UserGuide/files/GUID-633FE541-7E47-40F7-B98F-618FDCD8B1F6.htm) | The control title does not identify which analysis is intended. Roadway sight distance additionally depends on alignments/profiles/corridors, which are outside this issue's surface-only context. |
| **Drape Image** | Reshapes an already inserted image to follow surface relief and assigns a render material. Image smaller than surface covers only its footprint; larger images are cropped at the surface boundary. Surface triangles must display for the operation, and Autodesk's workflow uses Realistic material display. [To Drape Images on Surfaces](https://help.autodesk.com/cloudhelp/2024/ENU/Civil3D-UserGuide/files/GUID-FF3BB40B-A763-4A61-B9F6-6768423686EA.htm) | GoSurvey must define supported image entity/rendering and whether the image is persistently linked to the surface. This is distinct from merely placing a flat image. |
| **Move to Surface** | The documented “Move Blocks to Surface” moves selected block references vertically so each insertion point lies at the surface elevation. [To Move Blocks to a Surface Level](https://help.autodesk.com/cloudhelp/2024/ENG/Civil3D-UserGuide/files/GUID-BBF8F59A-9929-4F45-8FB9-0685D5AF0753.htm) | Autodesk's current command is explicitly for block references, not arbitrary entities. Issue text says “Move to Surface,” so the entity set and behavior should be confirmed in GoSurvey requirements. |
| **Create Profile** | A Civil 3D surface profile samples one or more surfaces along a horizontal alignment, optionally with offset profiles and a station range; it may be displayed/saved in a profile view. [To Create a Surface Profile Along an Alignment](https://help.autodesk.com/cloudhelp/2026/ENU/Civil3D-UserGuide/files/GUID-C359E9E2-D82D-4057-8E8D-A715BA15117A.htm), [Workflow: To Create Profiles](https://help.autodesk.com/cloudhelp/2026/ENU/Civil3D-UserGuide/files/GUID-F1056103-2DDD-4D05-AE0D-CD1C6FA63052.htm) | This initially conflicted with REQ-145. On 2026-11-06 the user approved adding the documented alignment-based existing-ground profile and saved profile view. `QUICKPROFILE` remains the temporary two-point graph; vertical design tangents and curves stay in issue #1163. |
| **Data Shortcut** | Creates a pointer from a source drawing to a shareable Civil 3D object, then creates a read-only data reference in a consumer drawing. References can synchronize with source edits. Surface shortcuts require a working folder/project association and source drawing. [About Data Shortcuts](https://help.autodesk.com/cloudhelp/2022/ENU/Civil3D-UserGuide/files/GUID-E91D2116-0F01-4A6B-B9C6-A47ED56F0F5F.htm), [How to Use or Create Data Shortcuts](https://help.autodesk.com/view/ACADWEB/ENU/?caas=caas%2Fsfdcarticles%2Fsfdcarticles%2Fhow-to-create-a-data-shortcut-in-Civil-3D.html) | This is a multi-drawing project/reference system, not simply export/share. Existing GoSurvey project requirements and sequencing must be checked before treating it as in scope. |

## GoSurvey constraint cross-check

- REQ-086 already specifies point-file linkage and should be used for that ribbon entry.
- REQ-145 continues to specify `QUICKPROFILE` as a session graph. The user separately approved the conventional alignment-based surface profile and saved profile view; REQ-513 records that decision and excludes vertical design tangents/curves tracked by issue #1163.
- REQ-143 says unsupported surface-tab commands stay disabled and identify themselves as not implemented. Once each behavior is accepted, that requirement should be amended to list the implemented actions and their remaining disabled controls.
- Autodesk documentation does not resolve product choices such as the supported label set, visibility mode, LOD persistence/accuracy, or whether blocks are the only “Move to Surface” targets. Those need explicit GoSurvey acceptance criteria.
